# نصب مستقل هر فروشگاه

۱. یک WordPress مستقل با HTTPS، پایگاه‌داده InnoDB و PHP 8.3 یا 8.5 آماده کنید. نسخه‌های دقیق آزموده‌شده در TEST_REPORT آمده‌اند. افزونه‌های PHP: mysqli، sodium، mbstring، gd، xml، zip و curl؛ ساعت و پایگاه‌داده را با UTC هماهنگ نگه دارید. برای بارگذاری ZIP هسته، upload_max_filesize حداقل ۱۶ مگابایت و post_max_size حداقل ۳۲ مگابایت باشد؛ کتابخانه و فونت PDF داخل بسته هستند.

۲. WooCommerce را از منبع رسمی نصب و راه‌اندازی اولیه کنید. HPOS را فعال کنید. ارز پایه را IRR (ریال)، مدیریت موجودی را فعال و روش‌های ارسال معتبر را تعریف کنید. داده‌های دو فروشگاه در دو نصب مستقل می‌مانند.

۳. ZIP افزونه `gold-commerce-core` را از افزونه‌ها ← افزودن ← بارگذاری نصب/فعال کنید. مسیر `wp-content/mu-plugins` باید برای نصب محافظ مالی قابل نوشتن باشد. این محافظ بعد از خاموشی Core از خرید تخصصی بدون موتور معتبر جلوگیری می‌کند.

۴. ZIP قالب `gold-commerce-theme` را از نمایش ← پوسته‌ها نصب و فعال کنید. برگه‌های قبلی، حریم خصوصی و محتوای موجود حفظ می‌شوند؛ صفحات پایهٔ مفقود ساخته می‌شوند.

۵. در «فروش طلا ← تنظیمات» قواعد مالی، نسخه قواعد، TTL نرخ، TTL مظنه، مهلت بازگشت، واحد نمایش، سیاست مهمان و روش تحویل را بازبینی و تأیید کنید. هیچ مقدار نمونه را به‌عنوان نرخ مالیات یا اجرت واقعی فروشگاه به کار نبرید.

۶. در همان صفحه، محتوای سبد و تسویه موجود را بررسی کنید و گزینه «راه‌اندازی تسویه کلاسیک» را تأیید کنید. این نسخه مسیر کلاسیک را آزمون می‌کند؛ checkout بلوکی برای طلا مسدود است. نسخهٔ پیشین محتوای دو صفحه برای بازیابی نگهداری می‌شود.

۷. کالاها را با SKU یکتا، مشخصات طلا، وزن خالص/کل/سنگ، مدل قیمت و موجودی محدود مدیریت‌شده تعریف کنید. برای محصول فیزیکی روش و نشانی تحویل قبل از صدور مظنه لازم است. برگه‌های سیاستی و هویت فروشنده را کامل کنید.

۸. رنگ، لوگو، بنر، ترتیب و تعداد بخش‌ها را در سفارشی‌ساز تنظیم کنید. فایل WOFF2 مجاز خودتان را در کنترل فونت بارگذاری کنید. تا آن زمان fallback محلی سیستم استفاده می‌شود. برای تجربهٔ کامل مدیر و ترجمهٔ همهٔ رشته‌های Woo، بستهٔ رسمی زبان فارسی WordPress/Woo را نصب کنید؛ برچسب‌های اصلی تسویه fallback محلی دارند.

۹. افزونهٔ آگاه اختیاری است. ZIP `gold-agah-connector` فقط شبیه‌ساز `MOCK_ONLY` و زیرساخت قرارداد دارد؛ آن را اتصال عملیاتی معرفی نکنید. تا تحویل API واقعی، فروشگاه با حالت standalone اجرا می‌شود.

۱۰. در محیط staging، fixture را فقط عمداً با `wp eval-file fixtures/install-sample.php --use-include` اجرا کنید. این دستور تنظیمات و کالاهای ساختگی می‌نویسد؛ برای سایت دارای داده واقعی نیست. درگاه TEST ONLY تنها در محیط غیرتولیدی و با test_mode روشن در دسترس است و هیچ پولی جابه‌جا نمی‌کند.

۱۱. درگاه واقعی منتخب فروشنده را نصب، واحد/مبلغ و callback آن را با Sandbox واقعی آزمایش و سپس فعال کنید. نصب افزونهٔ درگاه به‌تنهایی تأیید سازگاری نیست. در Production، test_mode خاموش و WP_ENVIRONMENT_TYPE برابر production باشد. حالت «به‌زودی/Coming soon» Woo را تنها پس از تکمیل پیکربندی و با تصمیم مدیر به حالت انتشار تغییر دهید؛ افزونه آن را پنهانی خاموش نمی‌کند. fixture آزمایشی این گزینه را عمداً برای آزمون محلی خاموش می‌کند.

۱۲. کران واقعی هر دقیقه، SMTP، بکاپ خارج از میزبان و مستثناکردن مسیرهای خصوصی از کش را طبق SECURITY_AND_BACKUP و OPERATIONS تنظیم کنید. پیش از انتشار، چک‌لیست INPUTS_NEEDED را کامل کنید.

به‌روزرسانی: بکاپ DB/files، نصب نسخه در staging، تست مالی، جایگزینی ZIPها، اجرای migration و بررسی سلامت. rollback کد تنها با توجه به نسخه schema و بدون حذف تراکنش‌های جدید مجاز است. برای بازگشت صفحات کلاسیک، محتوای ذخیره‌شده در `gc_checkout_page_backup` را در staging بررسی و به‌صورت کنترل‌شده بازیابی کنید.
